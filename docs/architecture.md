# 架构与维护

```text
QQ 私聊
   │
   ├─ 官方 QQ SDK 1.0.5（默认，仅 C2C intent）
   └─ OneBot v11 → 同机 NapCat Shell + Linux QQ（备用）
   │
主人配对 / 群聊过滤 / SQLite 入站去重
   │
串行命令与会话队列
   ├─ 明确记忆命令 → Node 内置 SQLite
   └─ 官方 Harness Agent → llm-pi-ai → Chat Completions API
          ├─ 原生会话 JSONL、重启恢复
          ├─ 原生摘要与上下文预算
          └─ 动态提示词：风格 + 最多 4,000 字符长期记忆

外部小工具 → feiyu notify → SQLite 通知队列
                                 │
                          独立调度，每秒检查
                                 │
                          固定主人主动发送
```

## 官方底座的边界

`src/profile.ts` 生成完整独立 profile，`src/plugin.ts` 是自写的 Cordis 插件，通过官方 `runProfile` 启动。`src/harness.ts` 使用官方 Agent create/resume、原生 stream/持久化/compaction；没有自造替代 Harness 的模型循环。

profile 只挂载运行内核、模型适配器、Token 计量、系统提示词、会话及 JSONL 持久化和本项目插件。`filesystem` 为 Harness 内部持久化提供服务，没有注册模型可调用的文件工具；空工具注册表也不暴露 Shell、Web、浏览器、MCP 或子代理。未挂载 Web UI、额外遥测插件或完整默认 bundle。

模型密钥通过 `apiKeyEnv` 引用并由 Harness 从环境读取，不把抽象凭据 seam 本身作为服务挂载。profile 只写配置引用，不写密钥。`tools` 注册表为空，模型不能自行操作数据库或创建任务；V1 长期记忆命令由确定性代码处理。

## 数据与幂等性

- SQLite 使用 WAL、`synchronous=FULL`、忙等待以及 `user_version` 检查；内置 SQLite 无独立数据库守护进程。
- `kv` 保存每通道主人、配对哈希/过期时间、会话 ID、轮次、记忆版本、最后入站时间、验收及心跳。
- `memories` 保存 ID、资料、来源和时间。每次写入变更记忆版本，下一次请求若版本不同便重建上下文；不自动从普通聊天提取事实。
- `inbox` 用通道和消息 ID 去重，持久队列串行调用命令或模型。明确记忆写入以来源消息幂等，计算好的回复先保存再提交 QQ。
- `notifications` 保存固定目标、到期时间、幂等键、尝试次数、状态、回执与人工确认时间。相同幂等键、相同目标和内容返回原任务，不重复排队；不重写原到期时间。
- 官方 JSONL 保存近期会话和原生摘要。SQLite 的当前会话引用与 JSONL 通过停止写入后的一致性备份一起保存。

进程恢复时，处理中的入站任务重新排队；已经进入回复提交阶段的入站消息不自动重发。正在发送的通知变为 `unknown`，因为无法确定外部平台是否已经提交。明确临时故障有限重试，网络结果不明交由用户核查；外部消息系统无法靠本地事务保证“恰好一次送达”。

一次性配对码只存 SHA256 哈希，10 分钟有效，消费和主人替换用 SQLite 事务完成。配对接口有限速；替换必须先从服务终端创建允许替换的配对码。通道切换后重新配对，不猜测官方 OpenID 与普通 QQ 号的对应关系，也不把旧主人的排队通知改投新主人。

## 故障处理与并发

模型请求串行，QQ 通知调度独立于模型等待；模型延迟不会要求用户再发消息才能触发通知。模型单请求默认 180 秒超时，取消后不返回上一轮的旧回复。QQ 断线时不提交通知；发送过程中断线则标记结果不明。

同一服务的数据目录有独占 PID 锁，第二个运行实例拒绝启动。停止服务会等待已在运行的处理和发送结束，再释放 Agent、网关和数据库。空闲释放、配对替换与聊天处理协调执行，避免释放一个正在使用的会话。

日志只记事件名、任务 ID、通道和有限错误代码；不记聊天文字、模型请求正文或认证头。启动进程对标准输出及错误输出再做已配置密钥值脱敏，QQ SDK 自身 logger 关闭。数据库和 JSONL 是私人数据存储，需要按个人数据保护。

## 未来扩展入口

招聘、补货、新闻或天气小程序可在外部维护自己的监控状态，在发现变化后调用：

```bash
sudo feiyu notify --text '发现一个新职位：……' --idempotency-key jobs:site:job-id
```

幂等键由业务事件决定，不要每次抓取都随机生成，否则不能避免重复提醒。不要把 API Key 放进命令行参数或仓库。消息固定发送给当前通道已绑定的主人，不接受任意外部收件人。

周期任务可后续接 systemd timer 或独立调度器，按 `Asia/Shanghai` 解释时间。MCP 接口、网页抓取、浏览器及自动长期记忆均需单独设计；当前没有为未来功能常驻浏览器或开放网络控制面。
